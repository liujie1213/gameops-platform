# 游戏安全运营平台 · 本地联调版

这套工作台可接收游戏服务端上报的数据，按规则给出聊天和局后判定，跟踪处罚是否已由游戏执行。首次体验只需一台 Windows 电脑，不需要云服务器、域名或大模型密钥。

## 启动与停止

双击本目录的 `start.cmd`，保持启动窗口打开。浏览器会打开 `http://127.0.0.1:8765`；如果提示登录，输入启动窗口显示的**管理密码**。启动器需要 Python 3.10 或以上版本，并会尝试使用此电脑已有的 Codex Python 运行环境。

在启动窗口按 Ctrl+C 可停止服务，再次双击即可重开。默认管理密码随服务重新启动而改变；游戏、规则、来往数据和处置结果保存在 `data/gameops.sqlite3`，不会因关闭浏览器或重启服务而清空。模拟游戏有独立的账号库 `integration/data/simulator.sqlite3`。不要把上述数据文件或密钥发给他人。

## 第一次演练

1. 进入「游戏接入」，创建一款**独立测试游戏**，保存只显示一次的**游戏密钥**。在右上角选中这款游戏。管理密码用于登录工作台，游戏密钥用于游戏服务调用接口，二者不能混用。
2. 在「聊天黑白库」添加并启用黑库词条「代练接单」，匹配方式选「包含匹配」。保持默认的「仅观察」，双击 `game-client.cmd`，按提示输入游戏密钥。独立的模拟游戏会发送聊天、等级、15 条举报和一次普通爆破结算。在「聊天审核记录」检查拦截；在「局后判定」应看到命中第③组，但没有处罚指令。
3. 仅在这个测试游戏中，进入「规则配置」，把「命中后的动作」改为「执行处罚」并点击「发布规则」。再运行一次 `game-client.cmd`，会生成新玩家和新对局。模拟游戏将 6 小时冻结写入自己的账号库并回传执行结果。点击刷新，在「处罚记录」核对结果。历史观察记录不会被追溯处罚。

## 如何接入第一款真实游戏

请游戏后端提供脱敏的字段说明和样例：玩家及举报人 ID、举报时间、对局 ID、模式编号、当场等级、KD（含零死亡口径）、击杀数、对局玩家平均等级，以及冻结和回执的处理方式。不要提供生产密钥或真实玩家聊天记录。

接入方要在游戏服务端实现三处连接：聊天发送前调用判定接口并执行拦截；在等级变化、举报和对局结算时上报事件；定期领取处罚指令、在账号服务执行、回传结果。平台不能自行修改厂商账号。先用厂商测试服和「仅观察」核对数据，不要直接在正式服开启处罚。字段、幂等和重试约定见[游戏服务接入指南](integration/接入指南.md)，机器可读定义见 [OpenAPI 契约](integration/openapi.json)。

## 何时需要云服务器

本地开发和同机联调无需购买。等第一家厂商的测试服需要从远程持续调用时，再一起确定网络和部署位置：可使用厂商已有的测试环境或双方可访问的独立测试服务器，不一定要自己买云主机。不要通过路由器端口映射把本机启动窗口提供的开发服务暴露到公网。

当前是单机联调版，已接入的内容审核能力是同步黑白库，没有异步大模型复核；行为判定使用举报和局后战绩，没有伤害明细分析。购买服务器也不会使这一版自动达到商用要求。对外运营前仍需完成厂商适配、访问权限与租户隔离验证、备份恢复、监控告警、压力测试，以及误罚复核和解除处罚流程。
